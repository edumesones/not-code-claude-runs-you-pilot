# Agent Orchestrator

Coordinate multi-agent execution within the 9-phase feature development cycle.

## Triggers

- Automatically invoked when a phase starts and `docs/agents.md` exists
- Called by other skills (implementer, thinking-critically, etc.) when agents are assigned to their phase
- "Run agents for Phase X"
- "Orchestrate FEAT-XXX"

## Prerequisites

- `docs/agents.md` exists (generated by agent-designer)
- `docs/agents/{id}/RULES.md` exist for each agent
- Feature folder exists with phase-appropriate files

## Fallback

If `docs/agents.md` does NOT exist → skip orchestration, run phase in legacy single-agent mode.

## Core Logic

### 1. Read Phase Configuration

```
Input: Phase number + Feature ID
Process:
  1. Read docs/agents.md → Phase Assignments section
  2. Get list of agents assigned to this phase
  3. Determine execution order (parallel groups, sequential chains)
  4. Read each agent's RULES.md
```

### 2. Build Agent Contexts

For each agent, construct execution context:

```
Agent Context = {
  identity: RULES.md → Identity section
  rules: RULES.md → Responsibilities + Boundaries
  input: Phase-specific files (spec.md, design.md, tasks.md, etc.)
  previous_output: Output from previous agent in relay chain (if any)
  harness: harness.md → Self-verification checklist
  output_format: RULES.md → Output section
}
```

### 3. Execute Agents

#### Parallel Execution (Worktrees)

For agents that work on independent file domains:

```
1. Verify agents have non-overlapping file boundaries
2. For each parallel agent:
   a. Create worktree via fork-feature skill
   b. Write agent context to .claude/contexts/{feature}_{agent-id}.md
   c. Launch separate Claude session with agent RULES as system prompt
3. Monitor: check status.md updates from each worktree
4. Merge: when all parallel agents complete, sync worktrees
```

#### Sequential Relay (Task Sub-Agents)

For agents that review/analyze other agents' output:

```
1. Launch Agent A as Task sub-agent:
   - Prompt: Built from RULES.md + input context
   - Files: Only the files listed in RULES.md Input section
   - Expected output: As defined in RULES.md Output section

2. Collect Agent A output

3. Launch Agent B as Task sub-agent:
   - Prompt: Built from RULES.md + Agent A's output as input
   - Additional context: "Previous agent (A) produced: {output}"

4. Collect Agent B output

5. Continue chain until all sequential agents complete
```

#### Same-Session Sequential

For simple 2-agent relays where overhead of Task isn't justified:

```
1. Switch prompt context to Agent A's RULES.md
2. Execute Agent A's work
3. Capture output
4. Switch prompt context to Agent B's RULES.md
5. Provide Agent A's output as context
6. Execute Agent B's work
```

### 4. Validate Results

After all agents complete:

```
For each agent:
  1. Read agent's harness.md → "After Completing" checklist
  2. Verify all deliverables exist
  3. Verify output format matches RULES.md specification
  4. If validation fails:
     a. Log failure to context/session_log.md
     b. Retry agent once with error context
     c. If still fails → escalate to user
```

### 5. Update Status

```
Update docs/features/FEAT-XXX/status.md:
  - Phase progress
  - Agent execution log:
    | Agent | Status | Duration | Output |
    |-------|--------|----------|--------|
    | A1    | ✅     | ~X min   | {summary} |
    | A2    | ✅     | ~X min   | {summary} |
```

## Phase-Specific Orchestration

### Phase 2: THINK CRITICALLY

```
Trigger: After human completes Steps 1-8 of analysis
Agents: A6 (architect) — adversarial review

Orchestration:
1. Read analysis.md → verify Steps 1-8 complete
2. Launch A6 as Task sub-agent with:
   - Input: analysis.md + spec.md
   - Task: Execute Step 9 (Adversarial Review)
3. Append A6's output to analysis.md as Step 9
4. Check for AUTO-PAUSE conditions:
   - If critical red flag → PAUSE, notify user
   - If low confidence → PAUSE, notify user
5. Update status.md
```

### Phase 3: PLAN

```
Trigger: After implementation-planner produces design.md + tasks.md
Agents: A6 (architect) — design validation

Orchestration:
1. Launch A6 as Task sub-agent with:
   - Input: design.md + tasks.md + analysis.md
   - Task: Validate design against analysis findings
2. If verdict = "NEEDS REVISION":
   - Flag issues to user
   - Re-run implementation-planner with feedback
3. If verdict = "APPROVED" or "APPROVED WITH NOTES":
   - Append validation report to design.md
   - Proceed to Phase 4
4. Update status.md
```

### Phase 5: IMPLEMENT

```
Trigger: Branch created, tasks.md ready
Agents: A1 (implementor), A2 (reviewer), A3 (bug-detector), A5 (test-writer)

Orchestration:
1. PARALLEL LAUNCH:
   - A1 (implementor) → worktree OR main session
   - A5 (test-writer) → worktree (if parallel execution)

2. CHECKPOINT LOOP (every 3 tasks):
   a. A1 commits + pushes checkpoint
   b. Launch A2 (reviewer) as Task:
      - Input: git diff since last checkpoint
      - Output: review report
   c. If A2 verdict = "NEEDS CHANGES":
      - Pass feedback to A1 for fixes
      - A1 fixes → re-checkpoint
   d. Launch A3 (bug-detector) as Task:
      - Input: git diff + A2 review report
      - Output: bug report
   e. If A3 finds critical bugs:
      - Pass bug report to A1 for fixes
      - A1 fixes → re-checkpoint
   f. Continue to next 3 tasks

3. COMPLETION:
   - All tasks done
   - Sync worktrees if parallel
   - Final review pass (A2 + A3 on full diff)
   - Update status.md
```

### Phase 5.5: VERIFY

```
Trigger: Implementation complete, tests exist
Agents: A3 (bug-detector), A5 (test-writer)

Orchestration:
1. Run test suite
2. If failures:
   a. Launch A3 as Task:
      - Input: test results + failing test code + production code
      - Output: root cause analysis per failure
   b. Launch A5 as Task:
      - Input: A3's root cause analysis
      - Output: fixed tests OR identified production bug
   c. If production bug found → relay back to A1
3. If all pass → proceed to Phase 6
4. Update status.md
```

### Phase 6: PR

```
Trigger: Tests pass, ready for PR
Agents: A2 (reviewer), A4 (doc-writer)

Orchestration:
1. Launch A2 as Task:
   - Input: full git diff from base branch
   - Output: final review report
2. If A2 finds critical issues → back to Phase 5
3. Launch A4 as Task:
   - Input: git log + git diff + A2 report + test results
   - Output: PR description markdown
4. Create PR with A4's description
5. Update status.md
```

### Phase 8: WRAP-UP

```
Trigger: PR merged
Agents: A4 (doc-writer), A6 (architect)

Orchestration:
1. Launch A4 as Task:
   - Input: all feature docs + session_log + decisions + blockers
   - Output: wrap_up.md
2. Launch A6 as Task:
   - Input: design.md + analysis.md + implementation results
   - Output: architectural learnings
3. Append A6's learnings to wrap_up.md
4. Update status.md → Phase 8 ✅
```

## Error Handling

### Agent Fails to Produce Output
1. Log error to `context/session_log.md`
2. Retry once with additional error context
3. If still fails → skip agent, notify user, continue phase

### Agent Violates RULES.md
1. Detect via harness.md validation
2. Discard output
3. Re-run agent with explicit reminder of boundary
4. If repeated violation → skip agent, notify user

### Relay Chain Breaks
1. If Agent B can't process Agent A's output:
   - Log incompatibility
   - Try Agent B with raw phase context (skip A's output)
   - If still fails → escalate to user

### Worktree Merge Conflicts
1. Use git-automator conflict resolution protocol
2. If unresolvable → notify user, show conflicting files

```markdown
**Timestamp:** {datetime}
**Agents invoked:** {list}
**Execution model:** {parallel/sequential/hybrid}

| Step | Agent | Action | Duration | Result |
|------|-------|--------|----------|--------|
| 1 | A1 | Implement tasks 1-3 | ~X min | ✅ 3 tasks done |
| 2 | A2 | Review checkpoint 1 | ~X min | ⚠️ 1 warning |
| 3 | A3 | Bug scan | ~X min | ✅ No critical bugs |

**Overall result:** Phase {N} complete
**Next phase:** {N+1}
```

This log is appended to `docs/features/FEAT-XXX/context/session_log.md`.
